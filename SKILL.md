# Palantir HTML slides

1. Turn the supplied brief, notes, or script into one takeaway per slide. Default to one main point plus 1–3 supporting points, with a hard ceiling of 6 independent information points in the final visible state. Count each distinct claim, metric, list item, or process stage once, including the headline when it adds a claim. Split a slide before exceeding the ceiling. Read [the information budget](references/layout.md#information-budget) before outlining. Keep the speaker's sequence, preserve source figures and quotes, and place a reveal at each meaningful beat.
2. Copy [assets/deck.html](assets/deck.html) to the output HTML. Set the document title and language. Replace the one insertion marker with slide definitions using the existing helpers. Read [references/layout.md](references/layout.md) for their signatures and layout patterns.
3. Default to the original four palette roles. Apply user-provided canvas, foreground, accent, and surface overrides as CSS variables. Set the requested reveal mode on the HTML element and default to automatic reveals. If the user supplies a logo, embed the original asset as an image data URL in the deck brand template and set descriptive alt text. Use the [customization instructions](README.md#customize-a-deck). Use oversized, left-aligned type, generous negative space, and brief black capsules only where they carry information. Use flat pixel cells for meaningful quantitative comparisons or clearly decorative motifs. Keep the presentation standalone and usable offline.
4. Check every slide at its final state and sample intermediate reveals. Count its independent information points and split any slide above 6. Preserve large type and generous spacing when reducing density. Verify that content stays inside the canvas and panels, capsule groups have equal gaps, highlights clear the text below, and pixel graphics stay inside their intended region. Verify that reveals finish on the current page, page turns work during playback, backward navigation behaves correctly in the selected mode, and full-screen mode hides all deck controls. Use a real browser when available.
5. Deliver the standalone HTML. Explain the keyboard controls briefly. If relevant, distinguish the browser's full-screen notifications from the deck's controls.

Keep the template's 1600 × 900 canvas, matching surrounding background, and reduced-motion support. Keep page turns manual in both reveal modes. Press F to enter full-screen and use the browser's Esc behavior to leave it.
